# 실험 설계 — 근거 데이터셋 기반 쉬운말 변환 검증 파이프라인

목표: 「본선 심사 → 발표 심사」 통과. 대회 평가 기준은 ①주제 적합성 ②실현 가능성이며, 발표 심사에서는 "왜 이 결과를 믿어도 되는가"를 15분 안에 증명해야 합니다. 이 설계는 그 증명 재료(반박 로그·정량 지표·held-out 검증)를 실험 산출물로 남기는 것을 1차 목적으로 삼습니다.

## 방법론: 반박 우선(falsification-first)

새 항목을 앵커 사전·검증 축·평가 지표에 넣기 전에, 먼저 그것을 깨뜨리는 반례를 스스로 찾는다. 반례를 찾지 못한 것만 채택한다. 자기 자신이 설계한 테스트로 자기 자신을 통과시키는 것(선택 편향)은 채택 근거로 인정하지 않는다 — 반드시 held-out(설계자가 미리 보지 않은) 자료로 재확인한다.

기존 자산에 대한 1차 반박 결과는 상단 대화 요약 참고. 이 문서는 그 결과를 반영한 3개 트랙 + Track 0으로 구성한다.

## Track 0 — 근거 데이터셋 정화 (최우선, 다른 트랙의 전제조건)

**문제:** 현재 `data/glossary_expanded.md` 76개 항목 중 19개가 정부 원문이 아니라 자체 요약이고, `demo.py` 테스트 문장 7개는 전부 가상의 예문이다. "임의 생성 금지" 제약을 지키려면 이 두 가지부터 실제 자료로 교체해야 다른 트랙의 결과가 의미를 가진다.

| 작업 | 방법 | 산출물 |
|---|---|---|
| 자체 요약 19개 항목 교체 | FSS 파인 「금융용어사전」 538개 원문(이미 8/7 조사에서 수집 완료 — 재사용)에서 해당 표제어의 공식 정의문을 그대로 발췌. 정의문이 길면 재요약하지 않고 `core.py`의 `constrained_clause`(숫자 없는 첫 절만 취하는 결정적 규칙)를 그대로 적용 | 자체 요약 0개인 `glossary_v3.md` |
| "알기쉬운 금융용어"(114개, 순화어 방식) 재시도 | 8/7 조사에서 크롤링 경로를 못 찾고 중단된 지점. fss.or.kr 업무자료 게시판을 재탐색하거나, 국회도서관·정책브리핑 등 재게시 경로 확인. 이 소스는 "정부가 이미 만든 쉬운말 대응표"라 재요약 리스크가 구조적으로 없어 최우선 대상 | 확보 시 사전에 병합, 실패 시 배제 사유 기록 |
| 실제 상품설명서·약관 원문 확보 | `data/`에 현재 실제 약관 파일이 없음. 금융소비자정보포털(파인), 은행연합회 소비자포털, 각 사 공시실에서 예금·적금·신용대출·신용카드·보장성보험 5종의 **실제 공시 문서**를 원문 그대로 수집(가공·재작성 금지) | `data/disclosures/` — 상품별 원문 텍스트 |
| 테스트 문장 교체 | `demo.py`의 SAMPLES 7개(가상 예문)를 위 실제 공시 문서에서 발췌한 문단으로 교체 | held-out 실험에 쓸 실 문단 집합 |

이 트랙이 끝나기 전까지 Track A·B·C의 결과는 "실제 서비스에 쓸 데이터로 검증됐다"고 발표 자료에 쓸 수 없다.

## Track A — 의미보존 검증 Agent 고도화

현재 축②(조건·예외절)·축③(단정 강화)은 키워드 사전 매칭 수준이라 "함의(entailment)가 뒤집혔는지"는 못 본다. 명세서가 이미 지목한 이 격차를 실제로 메우는 트랙.

1. **축② — NLI 함의 검사**
   - 후보 모델: KLUE-RoBERTa를 KorNLI/KLUE-NLI로 파인튜닝. 단, KorNLI는 영어 SNLI/MultiNLI의 기계번역본이라 "임의 생성 아님" 기준에서 경계선에 있음 — 학습·사전점검용으로만 쓰고, **최종 판정 근거로는 도메인 데이터를 반드시 병행**한다.
   - 도메인 검증셋: 금융감독원 「금융분쟁조정사례집」(실제 분쟁 사례 — 조건절을 잘못 읽어 생긴 실제 민원)에서 원문·오독 사례 쌍을 추출. 이것은 재구성이 아니라 실제 발생한 사례이므로 "임의 생성"에 해당하지 않는다.
   - 판정: (원문 조건절, 재작성문) 쌍을 premise-hypothesis로 넣어 entailment 확률 임계값 이하면 불합격.
2. **축③ — 소수거부권 앙상블**
   - 명세서가 이미 설계해 둔 방식. 서로 다른 프롬프트/모델 호출 2~3개 중 하나라도 "단정 강화 의심"이라 하면 불합격 처리(자기평가 편향 방지가 목적이므로 다수결이 아니라 소수거부권).
3. **유창성(fluency) 검사 — 신규 축, 명세서에 없던 격차**
   - "약정금리" 사례처럼 문법이 깨졌는데 축①②③은 다 통과하는 거짓 합격을 막는 축. Kiwi로 재작성문을 재구문분석해 미완성 구/중복 조사 등 문법 오류 패턴을 탐지하거나, perplexity 기반 임계값 사용.

**반박 계획(이 트랙 자체를 검증하는 법):** Track 0에서 확보한 실제 공시 문서 문단에 대해, 일부러 조건절을 삭제/반전시킨 버전을 만들어(★이 왜곡 자체는 "테스트용 부정 예시" 생성이지 근거 데이터셋 생성이 아니므로 허용 범위) 축②가 실제로 잡아내는지 recall을 측정한다. 잡아내지 못하면 이 트랙은 기각.

## Track B — 재작성 파이프라인 실험

현재 `substitute()`는 "용어 뒤에 사전 정의문을 그대로 삽입"하는 수준(진짜 재작성이 아님, 8/7 조사가 이미 지목). 두 접근을 실제로 돌려 비교한다.

| 방식 | 설명 | 리스크 |
|---|---|---|
| A. 정의문 삽입(현행, 베이스라인) | 유지 — LLM 미호출, 결정적, 가장 안전 | 문장이 부자연스러움(이미 확인된 한계) |
| B. 제약 생성(LLM + terminology-aware constrained decoding) | 앵커 사전의 쉬운말 표현만 쓰도록 강제한 상태에서 LLM이 문단 전체를 자연스럽게 재작성 | 환각·의미 이탈 위험 → Track A 검증기가 반드시 앞단이 아니라 **뒷단**에서 걸러야 함 |

두 방식 모두 Track 0의 실제 문단 집합에 대해 돌리고, Track C 지표로 나란히 비교한다. B가 A 대비 가독성은 오르지만 검증 통과율이 크게 떨어지면(=LLM이 자주 의미를 왜곡하면) 발표에서 "그래서 A를 기본, B를 옵션으로 남겼다"는 정직한 결론을 낼 수 있다 — 이 자체가 실현 가능성 평가에 유리한 서사다.

## Track C — 평가 방법론

| 지표 | 방법 | 데이터 |
|---|---|---|
| 수치·기간·비율 보존율 | 결정적 diff (축①), 콤마·범위·배수 표현까지 커버하도록 정규식 보강 후 재측정 | Track 0 실 문단 |
| 조건·예외절 보존율 | NLI entailment recall/precision | 분쟁조정사례집 기반 held-out |
| 단정 강화 탐지율 | 소수거부권 앙상블 recall | 위와 동일 |
| 유창성 | 문법 오류 탐지율 + 사람 평가(3인 평정, 5점 척도) | Track 0 실 문단 |
| 가독성 개선폭 | 문장 길이·어휘 난도 기반 한국어 가독성 지수(예: 국립국어원 또는 선행연구의 공개 공식 사용 — 직접 고안 금지) 원문 대비 쉬운말 비교 | Track 0 실 문단 |
| 용어 커버리지 | 실제 공시 문서 샘플에서 앵커 사전 표제어가 실제로 몇 % 탐지되는지 | Track 0 실 문단 |
| 최종 사용자 이해도(가능하면) | 실제 타겟(고령층/금융취약계층) 소수 대상 A/B 이해도 퀴즈 — 시간 부족 시 생략하고 3인 전문가 평정으로 대체 | 신규 소규모 실험 |
| 보류율(Hold rate) | 재시도 후에도 불합격으로 남는 문단 비율 — 너무 높으면 서비스로서 무의미, 너무 낮으면 검증기가 느슨하다는 신호 | Track 0 실 문단 |

**평가 원칙:** 모든 지표는 Track 0에서 확보한 실제 문서로만 계산한다. 손으로 지어낸 예문으로 낸 수치는 발표 자료에 쓰지 않는다 — 심사위원이 "그 문장 어디서 났느냐"고 물었을 때 답할 수 있는 숫자만 남긴다.

## 우선순위 (남은 기간 기준)

1. Track 0 (사전 정화 + 실 문서 확보) — 이것 없이는 나머지가 전부 "임의 생성 데이터 기반"이라는 같은 반박에 걸림
2. Track A의 축② NLI (명세서가 이미 핵심 리스크로 지목한 항목, 발표에서 가장 많이 질문받을 지점)
3. Track C 자동 지표 (Track 0·A 완료 즉시 계산 가능, 발표 자료의 정량 근거)
4. Track B (여유 있을 때 — 실패해도 "A를 기본값으로 채택한 근거"라는 정직한 결론으로 전환 가능)
5. 사람 평가(이해도 테스트) — 시간이 허락할 때만, 없으면 전문가 평정으로 대체

## 심사기준 매핑

- **주제 적합성**: 금융취약계층 대상 포용적 금융서비스 취지와 직결 — Track C의 이해도/가독성 지표가 이를 정량 증명
- **실현 가능성**: "반박에서 살아남은 것만 채택"이라는 방법론 자체 + Track A의 held-out recall 수치가, 이 서비스가 데모용 트릭이 아니라 실제로 검증된 파이프라인임을 보여주는 근거가 된다
